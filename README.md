# Remix SSR на Deno

Пример приложения [Remix](https://remix.run/) на [Deno](https://deno.com/) с серверным рендерингом
(SSR).

Remix v2 продолжает развиваться как [React Router](https://reactrouter.com/) в режиме фреймворка,
поэтому пример собран на React Router 8.

## Параметры деплоя

| Поле | Значение |
| --- | --- |
| Сборка | Railpack |
| Путь до директории проекта | `/` |
| Команда установки зависимостей | оставьте пустым |
| Команда сборки | `deno task build` |
| Команда запуска | `deno task start` |
| Порт приложения | `3000` |
| Путь проверки состояния | `/` |

Railpack видит `deno.json` и собирает проект в Deno. Команды сборки и запуска обязательны: сам
Railpack для Deno не собирает проект и не знает, как запустить сервер React Router. Задача `build`
собирает приложение (`react-router build`), задача `start` запускает сервер `react-router-serve`
с нужными правами Deno. Сервер слушает порт из переменной окружения `PORT` — её передаёт
платформа, — а без неё первый свободный, начиная с `3000`.

В демо нет `deno.lock`: версии пакетов выбираются при сборке по диапазонам из `package.json`.

Версия на Node.js — `app-example-remix-ssr`, статическая — `app-example-remix-deno`.

## Что показывает пример

- `/` — страница рендерится на сервере при каждом запросе: время рендера, `process.version` (в
  Deno — версия Node.js, с которой он совместим) и `User-Agent` приходят из `loader` и уже
  подставлены в HTML.
- `/about` — вторая страница приложения.
- `/api/hello` — ресурсный маршрут, отдаёт JSON.

## <a name="dev"></a>Локальный запуск проекта

```bash
# установка зависимостей
deno install --allow-scripts

# сборка для продакшн
deno task build

# запуск собранного серверного приложения
deno task start
```
